# ACWM-Phys baseline (이슈 #4): DINO-WM 8개 환경을 ACWM-DiT-S 이상의 학습량(predictor 933,334 step × 배치 24 = 2,240만 예측 프레임)으로 학습하고 평가한다.
# 형식은 queue/scheduler.py 머리말. 먼저 repro/colab/acwm_baseline_prep.sh 로 시작점과 설정 파일을 $ACWM_BASE 에 만든다.
#   bash repro/queue/start.sh repro/jobs/acwm_baseline.txt
# 학습: repro/colab/acwm_long.py. 토큰·디코더 목표 프레임을 캐시하고 predictor 와 디코더를 같은 배치로 매 step 갱신한다.
#   20,000 step 마다 검증하고 state 를 저장한다 (작업이 죽으면 다시 띄워 이어 간다).
#   --tf32 --amp (bf16 autocast) --compile. --images_cpu: 디코더 목표 프레임(uint8 224 px)은 RAM 에 둔다. need= 는 GPU 에 올릴 토큰 크기 + 여유.
#   시작점: Cloth Move·Push Sand·Stack Cube·Push Rope 는 HF baseline_x15/<run>/ 의 state (이슈 #4 §8 의 Colab 실행이 멈춘 곳),
#   Pour Water 는 train_pw_h1f5 의 6 epoch 체크포인트, Push Cube·Robot Arm·Reacher 는 처음부터.
#   디코더 상한은 원래 실행의 디코더 step 의 4배, 새 환경은 250,000.
# 평가: ckpt_tools.py build 로 검증 손실이 가장 낮은 predictor·디코더를 train.py 형식($DINO_TRAIN/outputs/acwm_base_<env>)으로 묶고
#   eval_acwm_phys.py (Pour Water 는 eval_pour_water.py) 를 ind_test·ood_test 의 모든 에피소드에 돌린 뒤 물리량을 잰다.
# 학습 3개와 평가가 GPU 를 나눠 쓴다. 평가 줄을 뒤 학습보다 앞에 두어 끝난 환경의 평가가 먼저 슬롯을 받는다.
